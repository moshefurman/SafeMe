## למה המיגרציות כתובות ידנית

Drizzle משמש כאן **לטיפוסים בלבד**, לא לייצור DDL. מקור האמת הוא קובצי
ה‑SQL תחת `migrations/`, מהסיבה הפשוטה שאף מחולל סכמה לא מייצר נכון את
מה שהמערכת הזו נשענת עליו:

* מדיניות Row Level Security
* חלוקת טבלה לפי טווח זמן ופונקציה שיוצרת מחיצות
* טריגרים שהופכים טבלה ל‑append‑only
* הרשאות מפורטות לשני תפקידי DB נפרדים

`src/db/schema.ts` משקף את ה‑SQL. **שינוי במיגרציה מחייב שינוי מקביל שם.**

ALTER ROLE safeme_owner WITH PASSWORD '...';
ALTER ROLE safeme_app   WITH PASSWORD '...';

## בידוד דיירים — איך זה עובד

כל טבלה עם נתוני לקוח נושאת `tenant_id` ומוגנת במדיניות RLS אחת:

```sql
USING (app.is_platform() OR tenant_id = app.current_tenant())
```

הקשר הבקשה נקבע ב‑`SET LOCAL` בתוך טרנזקציה, ולכן פג בסיומה ואינו נגרר
לבקשה הבאה שתקבל את אותו חיבור מה‑pool:

```ts
await withTenant(pool, tenantId, async (tx) => {
  // כל שאילתה כאן רואה רק את המכשירים של הדייר הזה,
  // גם אם שכחנו WHERE tenant_id = ...
  return tx.query("SELECT * FROM devices");
});

await withPlatform(pool, { userId, reason: "טיפול בפנייה 4821" }, async (tx) => {
  // גישת צוות החברה, מעל הבידוד. מחייבת סיבה מתועדת.
});
```

### שלוש נקודות שקל לפספס

**1. האפליקציה חייבת להתחבר כ‑`safeme_app`.** RLS אינו חל על בעל הטבלה.
חיבור כ‑`safeme_owner` מבטל בשקט את כל הבידוד. `assertAppRole()` נכשל
בעליית התהליך אם מחרוזת החיבור מפנה ל‑owner או ל‑postgres.

**2. הקשר חסר פירושו דחייה, לא מעבר.** אם `app.tenant_id` לא הוגדר,
`current_tenant()` מחזירה `NULL`, וכל השוואה מולה מחזירה `NULL` — כלומר
אפס שורות. ברירת המחדל בטוחה.

**3. מחיצות מקבלות מדיניות משלהן.** מדיניות על טבלת האב חלה על שאילתות
שעוברות דרכה, אך לא על שאילתה שפונה ישירות למחיצה. לכן
`app.ensure_heartbeat_partition()` מפעילה RLS על כל מחיצה שהיא יוצרת.

## מה שהמבנה עצמו אוסר

שתי האזהרות הרגולטוריות מ‑§7.2 מעוגנות בסכמה ולא רק בתיעוד:

* ב‑`verification_profiles` אין ולא תהיה עמודה ל‑PAN, ל‑CVV או לתעודת
  זהות מלאה. רק טוקן מספק הסליקה, 4 ספרות אחרונות, ו‑hash עם salt.
* ב‑`signing_keys` אין עמודה למפתח פרטי. הוא חי ב‑KMS בלבד.

הערות `COMMENT ON TABLE` בבסיס הנתונים חוזרות על האיסור, כדי שמפתח
שיפתח את הטבלה בעוד שנה יראה אותו.

## חתימת מדיניות — למה מעטפה ולא JSON

הבעיה מ‑§5.1: הסוכן ב‑C# והשרת ב‑TypeScript מייצרים JSON שונה מאותו
אובייקט — סדר מפתחות, בריחת תווים עבריים, ייצוג מספרים. חתימה על JSON
שכל צד בונה מחדש הייתה נכשלת בייצור.

הפתרון: השרת חותם **פעם אחת** על הבתים שנשמרים במאגר, ואותם בתים בדיוק
נשלחים למכשיר:

```json
{
  "alg": "RSASSA-PSS-SHA256",
  "kid": "dev-policy-1",
  "payload": "eyJ2ZXJzaW9uIjo0Mi...",
  "signature": "d4Xk9m..."
}
```

הסוכן מפענח base64, מאמת חתימה על הבתים, **ורק אז** מפרסר JSON.
אין קנוניזציה ואין תלות בסדר מפתחות.

התאמה מדויקת לצד ה‑C#: `RSASSA-PSS` · `SHA-256` · אורך salt = 32 בתים,
שהוא ברירת המחדל של `RSASignaturePadding.Pss` ב‑.NET.

## אימות דו-שלבי — למה מימוש עצמי

`totp.ts` מממש את RFC 6238 ישירות ולא דרך ספרייה, משתי סיבות:
האלגוריתם קצר ולא השתנה מ-2011, והוא יושב בנתיב הקריטי של הנפקת
קודי הסרה — כל תלות חיצונית שם היא משטח תקיפה נוסף בשרשרת האספקה.

המימוש נבדק מול **ששת וקטורי הבדיקה הרשמיים** של ה-RFC, כולל
`T=20000000000` שמונה שלו חורג מ-2^32 ובודק את פיצול המונה.

## אימות טרי לפעולות רגישות

שלוש הרשאות דורשות אימות דו-שלבי **בעת הפעולה**, ולא רק בכניסה:

| הרשאה | למה |
|---|---|
| `policy.lowerFloor` | הפעולה היחידה שמרפה את המחגר |
| `uninstall.issueCode` | הנתיב היחיד לכיבוי ההגנה |
| `providers.manage` | שינוי כאן משפיע על כל המכשירים בבת אחת |

חלון הטריות הוא 5 דקות. חשבון מנהל שנשאר פתוח במחשב אינו מספיק
כדי לבצע אותן.

## צנרת הפקודות

אין דחיפה למכשיר ואין חיבור מתמיד. הפורטל יוצר פקודה בתור, והמכשיר
אוסף אותה בפעימה הבאה — תוך עד שלוש דקות. מכשיר כבוי פשוט יאסוף
כשיחזור.

שלושה כללים מעוגנים במבנה ולא רק בקוד:

* **לכל נעילה יש משך**, בין דקה ל‑24 שעות. נאכף ב‑`CHECK` בבסיס הנתונים.
* **פקודה נמסרת פעם אחת**. האיסוף והסימון קורים באותה שאילתה, עם
  `FOR UPDATE SKIP LOCKED`.
* **פקודה ישנה פוקעת**. מכשיר שחוזר אחרי שבוע לא ייחסם בגלל בקשה
  ששכחו ממנה.

בקשת שחרור מבטלת נעילה שטרם נאספה, אחרת המכשיר היה נועל ומיד משתחרר.

## S6 — מה הלאה
